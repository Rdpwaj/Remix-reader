# أتمتة بناء ونشر APK عبر GitHub ودليل الاستخدام المدمج لتطبيق «قارئ الفصول»

تهدف هذه الخطة إلى تجهيز منظومة بناء سحابية متكاملة عبر **GitHub Actions** تقوم بتوليد ملف **APK** لتطبيق «قارئ الفصول» ونشره تلقائيًا في كلٍّ من قسم **Releases** (للتنزيل المباشر بضغطة واحدة دون فك ضغط) وقسم **Artifacts**، بالإضافة إلى توفير دليل عربي شامل في الصفحة الرئيسية للمستودع (`README.md`) وبطاقة إرشادية تفاعلية داخل شاشة إعدادات التطبيق.

---

### مراجعة المستخدم والقرارات المعتمدة

> [!IMPORTANT]
> تم اعتماد القرارات التالية بناءً على اختياراتك لتسهيل استخراج وتثبيت ملف APK على الأندرويد:

- **القرار المعتمد 1 (آلية استلام APK على GitHub):** نشر ملف `ChapterReader.apk` تلقائيًا في صفحة **GitHub Releases** (إصدار جاهز للتحميل المباشر بصيغة `.apk` دون الحاجة لفك ملف `.zip`)، إلى جانب رفعه في قسم **Actions Artifacts** بعد كل عملية بناء.
- **القرار المعتمد 2 (التوثيق والدليل المصور بالخطوات):** إنشاء ملف `README.md` عربي مفصل في واجهة المستودع يشرح خطوات استخراج وتثبيت الـ APK والنسخ الاحتياطي، مع إضافة نافذة دليل تفاعلي خطوة بخطوة داخل شاشة **الإعدادات** في التطبيق (مع إمكانية نسخ ملف Workflow أو الأوامر بضغطة زر).

---

### 1. نظرة عامة والمفهوم الأساسي

- **ماذا يقدم هذا التحديث:**
  1. **بناء سحابي كامل مع صلاحيات النشر التلقائي (`contents: write`):** يقوم سير العمل على GitHub بتجهيز بيئة Java 21 وAndroid SDK وGradle 9.3.1، وإنشاء مفتاح التوقيع `debug.keystore` تلقائيًا، ثم بناء الحزمة ورفعها في **Releases** و**Artifacts**.
  2. **دليل مستودع GitHub (`README.md`):** يظهر مباشرة في الصفحة الرئيسية لمستودعك على GitHub باللغة العربية، ويوضح بالخطوات المرقمة كيفية تشغيل **Actions** أو التحميل المباشر من **Releases**.
  3. **بطاقة «دليل بناء APK عبر GitHub» داخل التطبيق:** قسم مخصص داخل شاشة الإعدادات يعرض الخطوات الأربع بوضوح مع أزرار لنسخ إعدادات GitHub Actions ومشاركتها.
- **الجمهور المستهدف:** مترجمو وقراء الروايات الراغبون في الحصول على نسخة APK مستقلة ومحدثة من مستودعهم على GitHub وتثبيتها مباشرة على هواتف الأندرويد بدون الحاجة لجهاز كمبيوتر أو Android Studio.
- **القيمة الأساسية:** إلغاء خطوة فك الضغط اليدوي لملفات Artifacts عبر توفير رابط تحميل `.apk` مباشر من صفحة **Releases**، وتوفير مرجع دائم داخل التطبيق وفي المستودع.

---

### 2. تجربة المستخدم والتصميم البصري

- **مسارات المستخدم الرئيسية (Key User Flows):**
  1. **مسار GitHub Releases (الأسرع للجوال):** يفتح المستخدم صفحة مستودعه على GitHub ⬅️ يدخل إلى قسم **Releases** ⬅️ يضغط على ملف `ChapterReader-debug.apk` فيبدأ التحميل والتثبيت فورًا على الهاتف.
  2. **مسار GitHub Actions اليدوي:** يفتح المستخدم تبويب **Actions** ⬅️ يختار **Build & Release Android APK** ⬅️ يضغط **Run workflow** ⬅️ يحصل على الـ APK من **Artifacts** أو من **Releases**.
  3. **مسار الدليل المدمج داخل التطبيق:** يفتح المستخدم تبويب **الإعدادات** ⬅️ يضغط على زر **«شرح استخراج APK من GitHub»** ⬅️ تفتح نافذة مرشد مقسمة إلى خطوات واضحة مع زر **«نسخ كود GitHub Actions»**.
- **الهوية البصرية والثيم:**
  - يتبع الدليل المدمج داخل التطبيق نظام ألوان **Material 3** الدافئ (الذهبي الكهرماني `#D97706` والأزرق الأردوازي `#1E293B` وثيم السيبيا الورقي المريح للعين).
  - استخدام خط **Cairo** للعناوين والخطوات المرقمة، وخط **Tajawal** للشروحات التفصيلية، مع بطاقات ذات زوايا دائرية (`18.dp`) وأيقونات واضحة لكل خطوة.

---

### 3. القرارات التقنية والمفاضلات (Trade-Offs)

- **القرار 1: الجمع بين GitHub Releases وActions Artifacts في نفس سير العمل**
  - *النهج المختار:* استخدام `actions/upload-artifact@v4` لرفع نسخة الأرشيف، متبوعًا بـ `softprops/action-gh-release@v2` مع صلاحية `permissions: contents: write` لنشر ملف `.apk` مباشر تحت وسم إصدار تلقائي (`latest-apk`).
  - *لماذا:* لأن GitHub Actions يغلف ملفات الـ Artifacts دائمًا داخل ملف `.zip` مما يصعّب فتحها أحيانًا على الجوال، بينما قسم **Releases** يتيح تنزيل ملف `.apk` صافيًا بضغطة واحدة على هاتف الأندرويد.
- **القرار 2: التوليد التلقائي لملف `debug.keystore` أثناء البناء السحابي**
  - *النهج المختار:* فحص وجود `debug.keystore` وإنشاؤه عبر أداة `keytool` داخل السحابة قبل تشغيل `gradle assembleDebug`.
  - *لماذا:* لأن ملف `.gitignore` يمنع رفع `debug.keystore` إلى GitHub، وتوليده تلقائيًا يمنع فشل البناء السحابي دون المساس بإعدادات التوقيع الأصلية.
